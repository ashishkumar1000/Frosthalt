- source_spec: `_bmad-output/implementation-artifacts/spec-1-1-scaffold-react-native-macos-app.md`
  summary: Jest `transformIgnorePatterns` does not match `react-native-macos` (hyphen-suffix) or arbitrary `@react-native-*` scoped packages, so any future test importing them directly would fail to transform.
  evidence: The allow-list boundary is `(@|/|\+)`; `react-native-macos` has a `-` after `react-native`, so it falls through to the ignore side and is not transformed. No current test imports `react-native-macos` directly (tests import `react-native`, which the pattern does match, and the suite is green), so nothing breaks today. The default `react-native` preset has the same gap, so this was not introduced by this story — but this is a react-native-macos project, so a later test that imports `react-native-macos` directly would hit `SyntaxError: Cannot use import statement outside a module`. Trivial to harden later by widening the allow-list to `react-native[\w-]*` / `@react-native[\w-]*`.

- source_spec: `_bmad-output/implementation-artifacts/spec-1-2-design-token-system-and-shared-visual-primitives.md`
  summary: White label text (#FFFFFF) over `systemOrangeColor`/`systemRedColor` (the amber/blocked status fills) may fall below WCAG AA 4.5:1 contrast in light appearance — the palette is owned by the frozen DESIGN.md and was not introduced or changeable by this story.
  evidence: `primaryForeground` is `#FFFFFF` (frozen) and the amber/blocked fills resolve to `systemOrangeColor`/`systemRedColor` (frozen). `#FFFFFF` on `#FF9500` (the nominal systemOrange hex) is ~1.9:1, well under AA; on `#FF3B30` (systemRed) it is ~3.3:1, still under 4.5:1. The label typography is 11pt/500 (label token), below the 14pt-or-bold AA threshold that relaxes to 3:1. This is a real contrast concern, but the palette is human-owned in DESIGN.md's frozen frontmatter and the Story 1.2 Boundaries pin the NSColor mappings, so the fix (darker fills, or a fill-dependent foreground) is a DESIGN.md renegotiation, not a patch here. Surfaced incidentally by the StatusBadge fill-wiring review; the systemGreen `#34C759` fill is closer (~2.6:1, still under) but the free state is less critical. No automated contrast assertion exists because the fills are opaque PlatformColor objects at runtime; a contrast check belongs in a later design-audit story.
